# `mantdoc` compatibility completion goal

This document is the execution contract for proving that the native Rust
`mantdoc` parser can completely replace `libmandoc-rs`.  It deliberately keeps
three kinds of evidence separate:

- upstream mandoc golden files prove the behavior that their expected output
  actually observes;
- an independent `libmandoc-rs` runner proves the owned AST, wrapper
  diagnostics, and legacy engine projection that upstream output files do not
  expose;
- the existing ManT audit ledgers prove behavior over real manuals from Linux,
  BSD, illumos, Apple, generators, and other production corpora.

A native snapshot generated by `mantdoc` is useful regression evidence, but it
is never an independent compatibility oracle.

## Non-negotiable boundaries

- The ManT workspace remains pure Rust.  It must not regain a dependency or
  dev-dependency on `libmandoc-rs`, a C shim, vendored mandoc, or `cc`.
- The legacy oracle lives under `$HOME/dev/tmp/mantdoc-oracle` and pins the
  crates.io release `libmandoc-rs = "=0.9.1"` in its own lockfile.
- Local corpora, build trees, databases, raw logs, and benchmark evidence live
  below `$HOME/dev/tmp`, never `/tmp` and never in a published crate.
- The stable compatibility baseline is checksum-pinned mandoc 1.14.6.  A later
  snapshot is a separately identified forward-compatibility track and cannot
  silently replace this baseline.
- Audits are exhaustive over their declared inventory.  Sampling is useful
  only for diagnosis and cannot satisfy a completion gate.
- A difference is complete only when it is fixed, traced to the audit
  infrastructure, or recorded as an explicitly approved intentional
  difference with a regression test.  Unknown and silently skipped cases are
  failures.
- Correctness and performance audits use release binaries.  Independent lanes
  and checksum-ordered shards run concurrently after one shared build.
- Changes are committed by function.  Each commit body records motivation,
  behavior or design, and focused plus broad verification.

## Authoritative inventories

The stable upstream archive contains 572 regression inputs:

| family | inputs |
| --- | ---: |
| char | 32 |
| eqn | 22 |
| man | 99 |
| mdoc | 276 |
| roff | 107 |
| tbl | 36 |

Its 1,189 expected outputs comprise 565 ASCII, 26 UTF-8, 68 HTML,
249 lint, 253 Markdown, and 28 tag files.  Every output must be compared or
assigned an explicit capability-based reason why it is not applicable.

The real-manual boundary is the union of the six checked-in audit ledgers,
keyed by `(corpus, path, source_sha256)`.  At the time this goal was frozen it
contained 45,036 unique source identities.  The shared fidelity baseline has
17,811 identities; the structure and layout ledgers contain 34,269 and 28,575
rows respectively.  The inventory includes Arch Linux, Debian, Fedora,
Alpine, FreeBSD, OpenBSD, NetBSD, DragonFly BSD, illumos, Apple OSS,
Miniconda, generated manuals, tbl/eqn sources, and the checked-in fixtures.

The ledgers, rather than a newly sampled download, define the final real-world
audit.  Original bytes must match their recorded digest.  A missing historical
source is a visible restoration blocker, not a successful skip.  Computation
may be reused only when bytes, logical path, parser configuration, resolver
environment, compression mode, and oracle version are equivalent.

## Execution order

The existing M3, M4, M5, M6, and M9 names remain reserved for conformance
lanes.  Project phases use names so logs cannot confuse a milestone with a
test lane.

### FIX-NOW: close known execution defects first

1. Re-verify the existing same-line conditional-body fix, including the GCC
   source `.if rF .nr rF 1`; do not rewrite already correct commits merely to
   reorganize them.
2. Exercise same-line, next-line, and braced bodies for `.if`, `.ie`, `.el`,
   and `.while`, including nested conditions and generated input.
3. Cover register changes, strings, user macros, ignored blocks, translation,
   control and escape characters, and macros or loops nested inside selected
   condition bodies.
4. Align terminal, numeric, string, negated, parenthesized, and character
   predicates with libmandoc, including the active escape character.
5. Make an authored roff control line appearing in AST text, engine IR, or
   rendered output a hard audit failure.  Detection must include short tokens
   such as `if`, `nr`, register names, and numeric operands.
6. Run focused parser tests, the full `mantdoc` and `mant-engine` suites,
   strict Clippy, current conformance lanes, and the affected real fixtures.

Exit requires every currently known defect to have a minimal pure-Rust
regression and no known control-line leak.

### UPSTREAM-GOLDEN: use existing upstream evidence before inventing more

1. Verify the archive and every source/output identity before selecting cases.
2. Execute all 572 inputs.  Existing smoke lanes must not be described as AST
   parity when they do not compare a complete AST.
3. Verify the immutable native canonical regression snapshot over all 572
   inputs before comparing upstream projections.  It is a self-regression
   asset, not an independent oracle.
4. Compare all 659 applicable ASCII, UTF-8, and HTML outputs byte-for-byte.
   M9 differences and errors both fail the strict gate.
5. Project and compare all 249 lint outputs, including severity, logical
   source, line, column, order, and message.  The sole current exclusion is
   the reported `Xr` manual lookup: it is emitted by the `mandoc` command-line
   driver after parsing against its host manual database, a capability neither
   libmandoc-rs nor mantdoc's parser owns.  The lint lane counts that exact
   external finding separately; no parser finding is normalized or ignored.
6. Classify every Markdown and tag golden.  If a renderer is outside the
   `libmandoc-rs` replacement contract, retain parser coverage and extract any
   tag, anchor, link, or IR assertion the golden can support.
7. Convert every discovered parser, validation, diagnostic, or rendering bug
   to a focused regression before fixing it, then rerun its complete upstream
   family.

Exit requires 572/572 inputs and 1,189/1,189 outputs to be strictly compared
or explicitly classified, with zero unreviewed applicable golden difference.

Current format classification is intentionally explicit:

| Upstream format | Count | Compatibility treatment |
| --- | ---: | --- |
| `ascii`, `utf8`, `html` | 659 | Strict byte-for-byte mantdoc renderer gate (M9). |
| `lint` | 249 | Strict parser diagnostic gate: severity, source, position, order, and message. One `Xr` host manual-database lookup is counted as a CLI-driver-only event. |
| `markdown` | 253 | A separate mandoc presentation backend, not a mantdoc or libmandoc-rs renderer contract. Every source remains covered by the immutable parser snapshot, lint when available, and M9 formats; ManT Markdown is validated as an engine output in the independent oracle/IR phase rather than matched byte-for-byte to a different product format. |
| `tag` | 28 | A mandoc tag-backend projection, not the raw AST `Node::tag` field: it adds generated section anchors and backend-selected source locations. `mantdoc-tag-diff` records the exact raw projection gap (currently 0/28 direct matches) so it cannot be mistaken for AST parity. Existing parser and engine anchor regressions retain validated explicit destinations; an engine-anchor projection and the independent AST oracle close the remaining semantic comparison. |

### TEST-INFRA: make the claim match the gate

- Maintain one machine-readable capability matrix mapping input/output sets to
  strict tests, observational tools, independent oracles, and exclusions.
- Give every lane machine-readable counts and fail on an incomplete shard.
- Build conformance tools once and run independent lanes concurrently.
- Keep native self-goldens labelled as regression assets.
- Keep CI and `scripts/check-mantdoc.sh` documentation synchronized with the
  actual lane set and strictness.
- Preserve exact per-case replay information and never update goldens
  automatically in response to a difference.

### ORACLE: compare contracts absent from upstream golden files

After upstream golden closure, build isolated release runners below
`$HOME/dev/tmp/mantdoc-oracle`:

- the pinned `libmandoc-rs` parser and renderers;
- the current `mantdoc` parser and renderers;
- a frozen pre-cutover legacy parse/lower runner;
- the current native parse/lower runner.

They emit versioned, implementation-neutral JSONL.  Full AST comparison covers
metadata, macro set, node topology and order, kind, macro, normalized text,
tag, equation, source coordinates, flags, list/display/font/author/enclosure,
compactness, offsets, widths, table cells, and bounded depth behavior.
Diagnostic comparison covers severity, source, coordinates, order, prose, and
wrapper-generated findings.  IR comparison covers document metadata,
sections, blocks, lists, displays, tables, inline style, links, cross-manual
references, anchors, diagnostics, and explicitly allowed provenance changes.

The harness uses deterministic hash shards, long-lived JSONL workers, crash
and timeout isolation, bounded resources, and a resumable SQLite database.
Exit requires all 572 upstream inputs to have zero unreviewed AST, diagnostic,
and IR difference.

### CORPUS-RESTORE and MASS-AUDIT: exhaust the existing real corpus

Restore and hash-check every source identity in the union of the six ledgers.
Every identity must be available, safely reusable in an equivalent execution
context, explicitly non-roff, or reported as a blocking missing source.

Run the release oracle without sampling over every applicable identity.  For
each source compare AST, diagnostics, engine IR, supported renderers, and
visible text; detect missing and additional text, leaked requests, panic,
timeout, resource exhaustion, and non-linear output growth.  Results are
checkpointed locally and summarized per corpus with totals for executed,
reused, excluded, equal, different, error, panic, timeout, and missing-source
states.

Exit requires zero unknown identity and a complete, replayable difference
inventory.  Fixes proceed by parser subsystem, each with a minimal regression,
the affected upstream family, the original real source, and all affected
shards re-run.  No unreviewed AST, diagnostic, IR, or renderer difference may
remain.

### REFACTOR and CLIPPY-REVIEW: simplify only behind proven behavior

Once compatibility differences are closed, unify physical sources, generated
input, inline reparse, replay, user macros, collected scopes, loops,
conditions, and includes behind an explicit input-event queue and typed parser
actions.  Use bounded iterative stacks, borrow physical input, own only
generated input, and centralize condition evaluation plus the register,
string, macro, control-character execution environment.

Split large modules at grammar and ownership boundaries, not arbitrary line
counts.  Avoid trait objects, recursive execution, opaque iterator chains, and
allocation-heavy functional style.  Review every Clippy exception, remove the
avoidable ones, prohibit broad exception scopes, retain `unsafe_code =
"deny"`, and pass strict all-target/all-feature Clippy on supported platforms.
Each behavior-preserving commit re-runs its affected upstream and real-corpus
shards.

### PERFORMANCE: optimize measured low-cost paths

Use release builds to compare the pre-refactor baseline, final `mantdoc`,
`libmandoc-rs`, mandoc, and groff over small, large, batch, macro-heavy,
mdoc-heavy, tbl, eqn, plain, gzip, and zstd cases.  Separate parse-only, AST,
IR, render, cold-start, throughput, allocation, and peak-memory costs.

Prefer eliminating repeated tokenization, replay copies, string clones,
location reconstruction, repeated normalization, and repeated macro argument
parsing; preallocate arenas, diagnostics, and bounded stacks where measured.
Do not add unsafe code, global mutable caches, or semantic shortcuts.  An
unexplained small-input regression above five percent, a material large-corpus
regression, or non-linear memory growth fails this phase.  Beating mature C
tools in every mode is not a requirement; explaining comparable measurements
is.

### NEXT-SNAPSHOT: keep future mandoc work separate

After the stable baseline closes, pin one explicit forthcoming mandoc snapshot
by revision and date, inventory its changed tests and behavior, and publish a
forward-compatibility assessment.  It does not silently change 1.14.6 golden
files or keep this goal open against a moving upstream head.

### FINAL-AUDIT: prove the final tree, not the pre-refactor tree

From a clean build, rerun known-defect regressions, all 572 upstream inputs,
all 1,189 classified outputs, the independent AST/diagnostic/IR oracle, all
six real-corpus ledgers, fuzz and resource tests, compression and concurrency
tests, strict Clippy, package source-set verification, and Linux, macOS, and
Windows CI.

Completion requires zero oracle error, zero unreviewed applicable difference,
zero leaked control line, zero panic, zero silent source loss, and no
unexplained performance regression.  Every approved intentional difference
has a test and concise rationale.  The repository contains no
`libmandoc-rs`, C/FFI, vendored mandoc, `cc`, or unsafe path, and its functional
commit sequence plus compact audit summary is reproducible from the recorded
versions, hashes, and commands.
