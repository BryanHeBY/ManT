# Ordinary item/name field handoffs

This is the N matrix for NR13. It covers ordinary `It BODY → Nm BLOCK`
execution, separately from the closed-language tbl enhancement. No public IR
field, schema, vendor patch or formatter event history is introduced.

## Independent evidence

The 45 full sources are generated by
`scripts/roff/fixtures/name_body_handoff_cases.py`. Every source ran the locked
pristine reference in ASCII, UTF-8, HTML, tree and lint profiles **before** its
behavioral assertion was written. `cases.json` binds source hashes, all 225
status/stdout/stderr hashes, exact UTF-8 rows and overstrike font cells.
The recorder runs formal reference preflight even when the binary exists.

Normal sources are lint-clean. `control-table` is deliberately native
unsupported tbl input (lint 4); it is an enhancement control, not claimed as
supported native syntax. The independent top-level name session is also in
the matrix. Existing recovered-cell, eight enclosing HEAD/function controls,
enclosure operand and historical matrices remain separate and unchanged.

The reference uses the fixed five-column section origin from `term_ascii.c`.
Only that proven common origin and device trailing SP are removed. Leading
source/native word cells, internal SP/NBSP and every physical blank row stay
in the recorded expectation; no per-line trim or whitespace folding supplies
the native golden result.

## Execution rule and consumers

Pinned `mdoc_term.c::termp_it_pre/post` assigns actual BODY offset after its
source-line entry and clears the list flags at post. `termp_nm_pre/post`
consumes that same live native field: HEAD and BODY have different geometry,
but no output-owner return retires cells, viscol or minbl. `term_flushln`
consumes accepted intervals in order; node geometry restoration does not
restore flags, accepted graph or buffer contents.

Engine assertions cover JSON text roundtrip, validation, hard breaks,
HEAD/BODY relation, exact CLI rows and two real Markdown readbacks. UI
assertions paint actual terminal cells at widths 40/78 and check fonts,
word searches, link activation and copied label ownership. The native inset
fixed-word U+00A0 seam uses the already selected reading SP projection;
Markdown can simplify structural alignment while preserving hard rows and
word boundaries. Those projections do not claim terminal geometry fidelity
at every viewport.

The independent bare-`\z`/Nm padding observation and AR01 repeated-margin
character behavior remain explicitly outside this repair's closure claim.

### Narrow viewport origin

The core tag/hang source declares width20n plus It's two-column buffer; Nm's
BODY adds six columns. In the UI the shared row thus has first origin3 and
continuation origin3+22+6=31. The existing readable-origins policy reserves
sixteen content cells at viewport40, reducing both origins by seven and
clamping the first to0. At viewport78 the first remains3. Tests compute these
origins from the fixed source declaration and published viewport rule, not
from candidate IR. Every internal word cell, font, hard row and original
logical layout remains checked; this is a viewport translation, not a new
native geometry golden.
